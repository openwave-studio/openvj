# 03 – UI: Resolume-inspired, OBS-native

## What Resolume gets right (and we keep)

Resolume Avenue/Arena's layout has held up for over a decade because it maps to how VJs think:

1. **Clip grid**: rows are **layers**, columns are **columns** (scenes/decks). Click a cell to launch that clip on its layer. Click a column header to launch the whole column across all layers.
2. **Layer strip** on the left of each row: opacity fader, blend mode, bypass (B), solo (S), clear (X), layer name.
3. **Composition master**: master fader, composition-wide effects, crossfader between layer groups A and B.
4. **Properties panel** with three tabs (Composition / Layer / Clip). Each shows transport, transform and an **effect stack** with collapsible parameter blocks.
5. **Browser** for Files, Sources, Effects, Generators and Compositions. Drag into the grid or onto an effect stack.
6. **Preview + Output monitors**: preview a clip before launching it.
7. **Dashboard**: 8 macro knobs per clip/layer/composition, the natural MIDI-mapping target.
8. **Toolbar**: BPM, tap, resync, metronome, and a "launch quantisation" setting (bar/beat/off).
9. **Mapping mode**: toggle it, click any control, move a MIDI knob, and they're linked.

We take the *ideas*, not the look. No copying of Resolume's artwork, icons or trade dress.

## Mapping onto OBS

OBS's main window is built around Scenes/Sources/Mixer docks. openVJ fits in two ways, and we should support both.

**1. Docks inside OBS (default)**

Each panel is its own `QDockWidget`, registered with `obs_frontend_add_dock_by_id`:

| Dock | Contents |
|---|---|
| `openVJ Clips` | Clip grid plus layer strips plus master. The main dock, meant to be large. |
| `openVJ Properties` | Composition / Layer / Clip tabs with effect stacks |
| `openVJ Browser` | Files, OBS Sources, Effects, Shaders |
| `openVJ Transport` | BPM, tap, Link, quantise, MIDI map toggle (could be a toolbar instead) |

Users arrange them like any OBS dock, and OBS remembers the layout. The OBS preview already acts as "Output". The openVJ preview monitor is a small `OBSQTDisplay`-style widget rendering the *cued* clip.

**2. Workspace window (performance mode)**

A menu item (`Tools ▸ openVJ Workspace`) opens a separate top-level window with the full layout above, re-parenting the same widgets. It's meant for a second monitor during a show while OBS's own window sits elsewhere. Same widgets and state, just a different container.

## Widget and tech choices

- **Qt 6 Widgets.** OBS uses Widgets, and Qt Quick/QML isn't guaranteed in every OBS distribution.
- **Clip grid**: a custom-painted `QAbstractScrollArea` (not a `QTableView` with delegates). We need fast repaints, drag and drop, animated playheads and many cells. Paint thumbnails from a `QPixmap` cache.
- **Thumbnails**: generated by a background job (FFmpeg seek to 10%, scale to 160×90, cache under `~/.config/obs-studio/plugin_config/openvj/thumbs/`). Shader clips get a snapshot rendered once on the graphics thread. Optional **live thumbnails** for playing clips at a low rate (2–5 fps), opt-in because they cost a GPU readback.
- **Faders and knobs**: custom `QWidget`s with fine-drag (Shift), double-click to reset, right-click for mapping, automation and BPM-sync menus.
- **Parameter UI is generated** from parameter descriptors (ISF JSON inputs, our effect definitions, and `obs_properties_t` for hosted OBS filters). Write one parameter-widget factory and every effect gets UI for free.
- **Theme**: follow OBS's current theme (OBS 30+ theming), so openVJ looks native in Yami and others, with a few accent colours for "playing", "cued" and "mapped".

## Interaction details worth getting right early

- **Launch modes per clip**: trigger, gate (play while held), toggle. Each has a **launch quantisation** (off, beat, bar, or inherit from composition).
- **Column launch** triggers every clip in the column at once. Empty cells either clear their layer or leave it untouched (a per-composition setting).
- **Cueing**: Shift-click loads a clip into Preview without launching it.
- **Per-layer transition**: duration in beats or seconds, with a blend type (crossfade, or any transition shader).
- **Parameter animation**: every numeric parameter has a small mode menu: static / LFO (sine, saw, square, random) / BPM-synced / audio band / MIDI / OSC.
- **MIDI map mode**: highlights every mappable control, and click-then-move binds it. Mappings are stored per composition, with optional **controller profiles** that include LED feedback (APC40, Launchpad, Twister, M32).
- **Undo** for structural edits (add/remove/move clip, effect add/remove). No undo for live parameter moves, as is normal for VJ tools.
